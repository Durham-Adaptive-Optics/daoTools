daoDAQ - Dao Data Acquisition Tool (v2.0.0)

Tool Overview:
The dao tools repository provides a data acquisition tool
named daoDAQ for the persistance of data from various
sources within an RTC system such as from files or shared memory.

To check you have the tool installed run

daoDAQ --version

-----------------------

The tool is designed to run as a server on the RTC system.
By default the server is hosted on port 62000, however the
--port option can be used to configure this upon launch

daoDAQ --port 73000

By default the tool will emit log output to standard output,
however if instead you want logs output to a file
you can specify an absolute path where you would like
logs to be output to a log file like so:

daoDAQ --log-file /var/log/daoDAQ.logs

To find other options available consult

daoDAQ --help

--------------------------

In order to aquire data on the system the DAQ tool must be
provided a DAQ configuration fro mwhcih to operate a aquisiation session
from; this configuration is specified is YAML 1.2 and conveys what
data on the system should be aquired along with where it will be stored
and how it will be aquired.

Once a DAQ configuation has been successfully applied, DAQ sessions
can be carried out. Each session is stored under a root storage directory
on the system and contains all of the aquired datafiles for that DAQ session.

The structure of the DAQ configuation contains two objects;
'session' containing general parameters for the aquisation session
and 'sources' containing a list of all sources which are to be captured
in a aquisition session.

The following table lists the available DAQ session parameters
and should be provided directly in the YAML root scope.  

DAQ Session Parameters:

.. list-table:: session policies
   :header-rows: 1

   * - Field
     - Presence
     - Data Type
     - Default
     - Description

   * - ``root_storage``
     - Required
     - String
     - 
     - Absolute path where session outputs are stored to on disk.

   * - ``group_name``
     - Optional
     - String
     - Timestamp (eg. 2026-04-22_14-30-45)
     - Name of session's group subdirectory (if grouping is enabled).

Important: Please note omission of configuration parameters
denoted as required will result in a parse error when the configuration
is applied by the DAQ tool and will result in an Error state that must
be recovered from .. ensure all parameters marked required are correctly
specified, whereas optional parameters are free to be omitted.

Currently the DAQ tool supports two types of sources that data can
be aquired from during a DAQ session. A file, which is simply copied
to the session output once the session begins; and a shared-memory
from which data samples are aquired in real-time and written to 
an output datafile also stored in the session output directory.

A source is added to a DAQ session configuation by adding a configuation
entry under the DAQ configuation 'sources' list. The following tables 
list the available configuration parameters for both source types.

File Source:
.. list-table::
   :header-rows: 1

   * - Field
     - Presence
     - Data Type
     - Default
     - Description

   * - ``uri``
     - Required
     - URI
     - 
     - Absolute path to the file, in the format ``file://<path>``.
 
Shared Memory:
.. list-table:: 
   :header-rows: 1

   * - Field
     - Presence
     - Data Type
     - Default
     - Description

   * - ``uri``
     - Required
     - URI
     - 
     - Absolute path to the shared memory, in the format ``smem://<path>``.
   
   * - ``metadata_only``
     - Optional
     - Boolean
     - False
     - Capture only the frame metadata, discarding the frame data.
   
   * - ``samples``
     - Optional
     - Integer
     - Unbounded sample target
     - Number of samples to record from the shared memory source. If omitted, collection is unbounded.
   
   * - ``format``
     - Required
     - Format Type
     - 
     - Format of the output datafile(s); possible options are: ``numpy``, ``fits``.
   
   * - ``file_rollover``
     - Optional
     - Integer
     - Unbounded chunk limit
     - Number of samples per output datafile, at which point a new datafile is created to house upcoming samples.
   
   * - ``daq_affinity``
     - Optional
     - Integer
     - No affinity
     - Set the cpu affinity of the data-aquisation thread.
  
   * - ``sink_affinity``
     - Optional
     - Integer
     - No affinity
     - Set the cpu affinity of the sink thread.
   
   * - ``buffer_limit``
     - Optional
     - Integer
     - Unbounded buffer limit
     - Sets an upper limit on the number of samples the DAQ buffer can hold.

Help: 
Here is an example of a DAQ session configuration that demonstrates
configuring a session to capture a file source and a shared memory source.

root_storage: /path/to/data/root
group_name: my_session

sources:
  - uri: file:///path/to/my/file.ext

  - uri: smem:///tmp/cblue.im.shm
    metadata_only: no
    samples: 1900
    format: numpy
    file_rollover: 70
    daq_affinity: 7
    sink_affinity: 7
    buffer_limit: 900

The Python DAQ API.

The Dao tools repository, in addtion to the DAQ tool itself, provides
a Python API module for interacting with the tool to enable seemless
inteegration and control of the DAQ tool within the wider system
and applications - for example the shared-memory viewer uses this
API to interface with the DAQ tool on the system.

The module exposes the following, contained inside the module 'daoDAQ'

import daoDAQ

- daoDAQ.API
Attempts to connect to the daoDAQ tool running on the system,
defaults to localhost and the default 62000 port but you can specify
these in the constructor. You can also specify wheter to launch
the DAQ tool with the specified parameters if no instance is currently available.

eg. api = daoDAQ.API(port=76_100, launch=true)

- daoDAQ.API.UploadConfiguration
Uploaded the provided YAML configuration string to the tool
and applied it; requires no session be currently running.

- daoDAQ.API.StartSession
Start the DAQ session, optionally will block until
session auto-end is detected.

- daoDAQ.API.AwaitSessionCompletion
Block until a auto-end comaptible session ends.

- daoDAQ.API.EndSession
Ends the current DAQ session.

---

The Python API is exposed on the command-line through the tool daoDAQClient
and exposes the same functionality although on the command line.

daoDAQClient --help.
